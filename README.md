# RoleLens · 岗位透镜

在浏览器内读取国考、省考和招聘岗位表。支持 `.xls`、`.xlsx`、`.csv`，文件不上传服务器。

在线使用：[RoleLens](https://zanelin117.github.io/role-lens/)

## 使用

构建后的 **dist/index.html** 可以直接双击打开，离线使用，无需启动服务。

1. 点击“导入表格”或拖入文件。自动寻找前 40 行内的表头，跳过空白表。
2. 选择一个工作表。“总表”和地区子表分别筛选，避免重复合并。
3. 左侧选择工作地点、学历、学位、政治面貌等常见条件，专业和备注支持包含文字；“任意列筛选”可以筛选其他所有原始列。点击标题右侧的“搜索”按钮打开全局搜索框，输入后按回车或点击“搜索”应用；取消或按 Esc 不改变已有条件。
4. 备注要求可包含或排除：应届、指定毕业届别、限男性、限女性、英语四/六级、法律职业资格、资格证书、户籍/生源、服务年限、体能测评、夜班、出差等。支持“应届高校毕业生，男性”等省略“限”字的列举格式。
5. 查看详情，核对全部原文和识别依据。可以收藏、排序、切换显示列、保存筛选方案、导出全部匹配岗位。

不同字段之间为“同时满足”，同一字段的多选值为“任一满足”。全局搜索用逗号分隔多个词，所有词均需出现。手动专业关键词筛选按原始文本包含匹配；个人信息自动匹配使用专业名称、代码及学历阶段判断。

工作地点与落户地点按原表的地区层级筛选：选择“福建省”会包含“福建省福州市”“福建省xx县”等地点，选择“福建省福州市”会包含其下属区县。省、市选项即使没有单独一行也会从完整地点生成，数量包含下属岗位；同时选择省、市或区县时岗位不重复。不推测原表未写明的区县归属，导出保留原始地点文字。

## 个人信息自动匹配

点击顶部“个人信息”打开填写窗口。填写最高学历、学位、毕业证专业、毕业年份、性别、政治面貌、应届身份、基层工作年限和定向经历，然后点击“保存并自动筛选”。可以补充其他学历，以及出生年月、英语成绩、法律职业资格和户籍 / 生源信息。

专业名称使用可搜索下拉框，收录 875 个本科专业。点击右侧箭头可浏览全部专业，输入专业名称、代码或专业类搜索，也可按专业类缩小列表；支持方向键选择、回车确认、Esc 收起。本科选择专业后自动填写代码与专业类。没有列出的旧专业、专科或研究生专业可按毕业证手动填写，不套用本科代码；“数字媒体”仍可进一步确认技术或艺术方向的完整名称。

- 本科专业分类按[教育部2026年本科专业目录](https://www.moe.gov.cn/srcsite/A08/moe_1034/s3882/202604/W020260427440749576927.pdf)识别。例如，网络工程对应 080903，属于 0809 计算机类。具体专业与整个专业类分别匹配，不混用本科与研究生目录。括号中的细分专业和研究方向另行核对。
- 自动识别学历的“仅限”“或”“及以上”、相应学位、党员 / 团员、性别、应届 / 指定届别、基层年限、项目完成情况以及服役年限。
- 年龄规则可选择“2027国家公务员招考公告”或“只按表格判断”。只有明确选择2027规则才应用该年度的一般年龄和2027届应届硕博放宽范围，不套用到其他年份。[2027国考公告来源](https://www3.xinhuanet.com/edu/20261013/ce6bf7dc36474dd68ecd90aa8b722f06/c.html)
- 默认显示“可报候选”：专业和学历已经匹配，且没有其他已识别条件明确不符的岗位。专业 / 学历范围尚未确认的岗位保留在“待核对”范围，可切换查看，不直接判为已排除。另可切换基础匹配、已排除或所有岗位。状态显示在职位代码旁，详情列出匹配与排除依据。
- 未识别专业、自设专业、英语多项任选、户籍 / 生源、体能和完整备注等保留为待核对，不据此断言可报或不可报。基础匹配仅表示已填写且已识别的基础条件匹配，仍需核对通用报考资格和招录单位审核要求。
- 保存信息时清除旧手动筛选条件，之后可继续叠加手动筛选。切换工作表或导入新表仍使用当前个人信息；“暂停匹配”可临时恢复手动模式。
- 勾选“记住本机个人信息”后，下次打开并重新导入表格会继续匹配。未勾选只在本次页面使用。“清除个人信息”移除本机保存。信息不上传，不要求姓名、身份证号。导出匹配结果带状态和理由，不附个人信息表。

“未注明”表示未识别到相应要求，不等于允许所有人报名。英语、证书等按关键词标记，备注中的任选关系和分数门槛需核对原文。“适合男性/女性”与强制限制分开。应届要求和具体届别也分别标注。

收藏按文件名和工作表存于当前浏览器；筛选方案最多保存 8 个。文件本身不持久化，刷新后需要重新导入。导出保留所有原始列，并附识别要求、来源工作表、原表行号；职位代码与电话按文本保留。

## 开发

需要 Node.js 20.19+ 或 22.12+。

```powershell
npm install
npm run dev
```

本地地址：http://127.0.0.1:5173

```powershell
npm test
npm run build
node scripts/verify-workbook.mjs '完整路径/岗位表.xls'
```

React + Vite，SheetJS 0.20.3（官方分发包保存在 vendor，参见 https://docs.sheetjs.com/docs/getting-started/installation/nodejs/）。Web Worker 解析大表以保持界面响应。构建时将脚本、样式和解析 Worker 内嵌为单个离线 HTML。

## 部署

通过 GitHub Pages 托管，无需后端服务。`.github/workflows/deploy.yml` 在推送到 `main` 或手动运行时，使用 Node.js 22 执行 `npm ci`、测试和构建，然后发布 `dist`。构建使用相对路径，同时支持仓库子路径和离线打开。

仓库 Settings → Pages 的部署来源需设置为 **GitHub Actions**。成功部署后可在 Actions 中查看网页链接；后续提交到 `main` 会自动更新网站。岗位表、导出文件、个人信息和本机验证文件不随网站发布。

## 数据限制

最大文件 60 MB。表头至少有两列，优先识别标准招录字段；岗位表有职位代码时跳过无代码的汇总/说明行。通用表格以第一个有两列内容的行作为表头。备注识别规则位于 `src/data.js`，可追加新表达及测试。
